# Webhooks: Setup, Events & Signature Verification

**Webhooks** are HTTP callbacks that notify your app when events happen (email delivered, opened, bounced, etc.). Instead of polling the API, Tratto pushes events to you in real-time.

## Register a Webhook

Create a webhook endpoint.

**cURL**
```bash
curl -X POST https://api.tratto.email/v1/webhooks \
  -H "Authorization: Bearer tratto_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "url":"https://yourapi.com/webhooks/tratto",
    "events":["sent","delivered","opened","clicked","bounced","complained","unsubscribed"]
  }'
```

**Response:**
```json
{
  "data": {
    "id": "wh_abc123",
    "url": "https://yourapi.com/webhooks/tratto",
    "events": ["sent", "delivered", "opened", "clicked", "bounced", "complained", "unsubscribed"],
    "secret": "whsec_xyz789...",
    "createdAt": "2025-06-30T12:00:00Z"
  }
}
```

**Save the `secret`** — you'll use it to verify signatures.

## Webhook Events

Tratto sends `POST` requests to your URL when these events occur:

| Event | Payload |
|-------|---------|
| `sent` | Email accepted by mail server |
| `delivered` | Mail server confirmed delivery |
| `opened` | Recipient opened email (pixel tracked) |
| `clicked` | Recipient clicked a link |
| `bounced` | Mail server rejected delivery |
| `complained` | Recipient marked as spam |
| `unsubscribed` | Recipient clicked unsubscribe |

## Webhook Payload

**Example:**
```json
{
  "id": "evt_abc123",
  "type": "delivered",
  "emailId": "email_xyz789",
  "recipient": "user@example.com",
  "occurredAt": "2025-06-30T12:00:10Z",
  "data": {}
}
```

## Verify Webhook Signature

Every delivery carries an `X-Tratto-Signature` header. It is **not** a bare hash
— it holds a timestamp and the signature:

```http
X-Tratto-Signature: t=1784977714054,v1=0b37dd97144dcdf176572a1b...
```

The signed string is the timestamp and the raw body joined by a full stop:

```
{timestamp}.{rawBody}
```

Verification therefore has four steps: parse `t` and `v1`, reject timestamps
outside a tolerance window, recompute the HMAC over `{t}.{rawBody}`, and compare
with `v1` in constant time.

**[Webhook Signature Verification](/en/docs/webhook-verification)** has working
implementations for Node, edge runtimes, Python and PHP, plus the delivery and
retry behaviour you should design around.

<Callout type="warn">
Signing the body on its own, or comparing the header directly against a digest,
will never match. Both are the mistakes we see most often.
</Callout>

## Prevent Replay Attacks

Use the `t` field from the signature header, not `occurredAt` from the payload.
`t` is covered by the signature and records when the delivery was signed;
`occurredAt` records when the event happened, and the two differ on retries.

The tolerance check is already part of the implementations in
[Webhook Signature Verification](/en/docs/webhook-verification).

## Rotate Webhook Secret

Generate a new signing secret.

**cURL**
```bash
curl -X POST https://api.tratto.email/v1/webhooks/wh_abc123/rotate-secret \
  -H "Authorization: Bearer tratto_live_..."
```

**Response:**
```json
{
  "data": {
    "secret": "whsec_new..."
  }
}
```

<Callout type="warn">
Rotation takes effect **immediately** — there is no overlap window, and the
previous secret stops working as soon as the new one is issued. To rotate without
dropping deliveries, deploy an endpoint that accepts either secret first, then
rotate, then remove the old one. See
[Secret rotation](/en/docs/webhook-verification).
</Callout>

Rotation also resets the failure counter and re-enables a webhook that had been
disabled after repeated failures.

## Test Event

Send a test webhook event to verify setup.

**cURL**
```bash
curl -X POST https://api.tratto.email/v1/webhooks/wh_abc123/test \
  -H "Authorization: Bearer tratto_live_..."
```

A test `sent` event is posted to your URL immediately.

## List Webhooks

Get all registered webhooks.

**cURL**
```bash
curl https://api.tratto.email/v1/webhooks \
  -H "Authorization: Bearer tratto_live_..."
```

## Webhook Deliveries

View delivery history for a webhook.

**cURL**
```bash
curl https://api.tratto.email/v1/webhooks/wh_abc123/deliveries \
  -H "Authorization: Bearer tratto_live_..."
```

**Response:**
```json
{
  "data": [
    {
      "id": "del_001",
      "webhookId": "wh_abc123",
      "eventId": "evt_abc123",
      "status": "success",
      "statusCode": 200,
      "deliveredAt": "2025-06-30T12:00:10Z"
    },
    {
      "id": "del_002",
      "webhookId": "wh_abc123",
      "eventId": "evt_def456",
      "status": "failed",
      "statusCode": 500,
      "retries": 3,
      "nextRetryAt": "2025-06-30T12:10:00Z"
    }
  ]
}
```

Tratto retries failed deliveries up to 3 times.

## Delete a Webhook

Unregister a webhook.

**cURL**
```bash
curl -X DELETE https://api.tratto.email/v1/webhooks/wh_abc123 \
  -H "Authorization: Bearer tratto_live_..."
```
