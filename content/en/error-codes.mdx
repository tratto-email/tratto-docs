---
title: Error Codes Reference
description: The eight error codes the Tratto API returns, and what to do about each.
---

The API returns **eight** error codes. They are deliberately generic: the code
tells you the *class* of problem and the HTTP status, while `message` carries the
specific detail.

Branch on `code`, not on `message`: messages are written for humans and can
change without notice.

## Error Format

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Webhook 'wh_abc123' not found.",
    "docs": "https://tratto.email/docs/api/errors#not_found"
  }
}
```

`suggestion` is present on some errors with a hint about the fix. Validation
errors add a `details` array: see below.

## The Codes

| Code | HTTP | Meaning | What to do |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | Missing or invalid API key | Check the `Authorization: Bearer` header |
| `FORBIDDEN` | 403 | The key lacks permission for this resource | Use a key with the right permissions |
| `NOT_FOUND` | 404 | The resource does not exist | Check the ID; it may belong to another workspace |
| `CONFLICT` | 409 | The resource already exists | Fetch or update the existing one instead |
| `VALIDATION_ERROR` | 422 | The request body failed validation | Read `details` for the offending fields |
| `RATE_LIMITED` | 429 | More than 500 requests in a minute | Back off exponentially and retry |
| `QUOTA_EXCEEDED` | 429 | Monthly email quota reached | Upgrade the plan or wait for the reset |
| `INTERNAL_ERROR` | 500 | Something failed on our side | Retry with backoff; contact support if it persists |

<Callout type="warn">
There are no resource-specific codes. A missing template, a missing contact and
a missing campaign all return `NOT_FOUND`. The resource is named in `message`,
not in `code`.
</Callout>

## Validation errors

`VALIDATION_ERROR` returns **422**, not 400, and includes a `details` array from
the schema validator identifying each field that failed:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed.",
    "docs": "https://tratto.email/docs/api/errors#validation_error",
    "details": [
      {
        "instancePath": "/to",
        "message": "Invalid email"
      }
    ]
  }
}
```

## Two codes share 429

`RATE_LIMITED` and `QUOTA_EXCEEDED` both return 429, and they need opposite
responses:

- **`RATE_LIMITED`**: you are sending too fast. Back off and retry; the request
  will succeed shortly. See [Rate Limits](/en/docs/rate-limits).
- **`QUOTA_EXCEEDED`**: you have used your monthly email allowance. Retrying
  will not help until the plan resets or is upgraded.

Treating them the same means retrying forever against a quota wall:

```javascript
if (error.status === 429) {
  if (error.code === 'QUOTA_EXCEEDED') {
    // Alert someone. Retrying cannot fix this.
    throw error;
  }
  await backoff();
  return retry();
}
```

## Handling errors with the SDK

`@tratto/email` throws `TrattoError`, which carries `code` and `statusCode`:

```javascript
import { TrattoError } from '@tratto/email';

try {
  await tratto.emails.send({ /* … */ });
} catch (error) {
  if (error instanceof TrattoError) {
    switch (error.code) {
      case 'VALIDATION_ERROR':
        // Fix the payload: retrying unchanged will fail again.
        break;
      case 'RATE_LIMITED':
        await backoff();
        break;
      case 'QUOTA_EXCEEDED':
        // Nothing to retry.
        break;
      default:
        throw error;
    }
  }
}
```
