# SDK Angular — Solo Lato Server

`@tratto/angular` è un SDK **lato server**. Non deve mai essere eseguito in un browser.

Una chiave API dà accesso completo al tuo workspace. Chi la possiede può inviare
email dai tuoi domini verificati, leggere la lista contatti, creare nuove chiavi
API, rimuovere membri del team ed eliminare il workspace stesso. Una chiave
spedita al browser è pubblica: si legge nel bundle JavaScript, nei DevTools e nel
tab di rete. Nessuna offuscazione cambia questo fatto.

Tutti gli SDK Tratto sono pensati per il server, così come quelli equivalenti
degli altri provider email. Di questo pacchetto non esiste una build per browser.

## Il tranello specifico di Angular

React ha un confine di compilazione tra codice server e codice client. **Angular
no.** Tutto ciò che scrivi in un componente, in un servizio o in un resolver
finisce compilato nel bundle del browser, anche in un'applicazione SSR. Il server
side rendering cambia *dove il codice viene eseguito la prima volta* — non
impedisce al codice di raggiungere il client.

La conseguenza è concreta:

```ts
// ❌ MAI — app.config.ts fa parte del bundle browser
export const appConfig: ApplicationConfig = {
  providers: [
    provideHttpClient(),
    provideTratt({ apiKey: 'tratto_live_...' }),  // spedita a ogni visitatore
  ],
};
```

Mettere la chiave in `app.config.ts` la pubblica. L'applicazione funzionerà lo
stesso, ed è proprio questo che rende l'errore facile da non notare.

## Dove può stare la chiave

Angular unisce una configurazione solo-server a quella del browser al momento del
render. I provider dichiarati in `app.config.server.ts` esistono **soltanto** nel
bundle server:

```ts
// app.config.server.ts — solo bundle server
import { mergeApplicationConfig, ApplicationConfig } from '@angular/core';
import { provideServerRendering } from '@angular/ssr';
import { provideTratt } from '@tratto/angular';

import { appConfig } from './app.config';

const serverConfig: ApplicationConfig = {
  providers: [
    provideServerRendering(),
    provideTratt({ apiKey: process.env['TRATTO_API_KEY']! }),
  ],
};

export const config = mergeApplicationConfig(appConfig, serverConfig);
```

`app.config.ts` resta pulito: niente `provideTratt`, niente chiave.

Poiché il provider esiste solo sul server, iniettare `TrattoService` in codice che
gira anche nel browser genera lì un errore "no provider". È il comportamento
voluto: fallisce in modo rumoroso invece di far trapelare la chiave.

## Pattern 1 — Chiama Tratto dalle tue route server (consigliato)

Il design più sicuro tiene Tratto completamente fuori dall'applicazione Angular.
Il tuo server espone un endpoint, il browser chiama quell'endpoint e il server
parla con Tratto usando l'SDK Node.

```ts
// server.ts
import {
  AngularNodeAppEngine,
  createNodeRequestHandler,
  isMainModule,
  writeResponseToNodeResponse,
} from '@angular/ssr/node';
import express from 'express';
import { dirname, resolve } from 'node:path';
import { fileURLToPath } from 'node:url';
import { Tratto } from '@tratto/email';

const browserDistFolder = resolve(
  dirname(fileURLToPath(import.meta.url)),
  '../browser',
);

const app = express();
const angularApp = new AngularNodeAppEngine();
const tratto = new Tratto(process.env['TRATTO_API_KEY']!);

app.use(express.json());

// Endpoint tuo — il browser non vede mai la chiave Tratto.
app.post('/api/contact', async (req, res, next) => {
  try {
    // Valida prima di inviare. Mai interpolare input utente in `from`.
    const { email, message } = req.body ?? {};
    if (typeof email !== 'string' || typeof message !== 'string') {
      return res.status(400).json({ error: 'Invalid payload' });
    }

    const result = await tratto.emails.send({
      from: 'Acme <hello@mail.acme.com>',
      to: 'support@acme.com',
      replyTo: email,
      subject: 'Nuovo messaggio dal form di contatto',
      text: message,
    });

    // Restituisci solo ciò che serve al client.
    res.json({ id: result.id });
  } catch (error) {
    next(error);
  }
});

app.use(
  express.static(browserDistFolder, {
    maxAge: '1y',
    index: false,
    redirect: false,
  }),
);

app.use((req, res, next) => {
  angularApp
    .handle(req)
    .then((response) =>
      response ? writeResponseToNodeResponse(response, res) : next(),
    )
    .catch(next);
});

if (isMainModule(import.meta.url)) {
  const port = process.env['PORT'] || 4000;
  app.listen(port);
}

export const reqHandler = createNodeRequestHandler(app);
```

Qui si usa [`@tratto/email`](/it/docs/sdk-nodejs), l'SDK Node: dentro un handler
Express non esiste l'injector di Angular, quindi l'SDK Node è la scelta naturale.

## Pattern 2 — Recuperare dati durante il render server

Se ti servono dati Tratto *mentre la pagina viene renderizzata*, inietta il
servizio e proteggi la chiamata perché avvenga solo sul server. Il provider di
`app.config.server.ts` rende la chiave disponibile lì e in nessun altro punto.

```ts
import { Component, inject, PLATFORM_ID, signal } from '@angular/core';
import { isPlatformServer } from '@angular/common';
import { TrattoService } from '@tratto/angular';

@Component({
  selector: 'app-newsletter-stats',
  template: `<p>{{ subscribers() }} iscritti</p>`,
})
export class NewsletterStatsComponent {
  private readonly platformId = inject(PLATFORM_ID);
  readonly subscribers = signal(0);

  constructor() {
    if (!isPlatformServer(this.platformId)) return;

    // Iniettato in modo pigro: la build browser non risolve mai il provider.
    const tratto = inject(TrattoService);
    tratto.analytics
      .getSummary({ period: '30d' })
      .subscribe((summary) => this.subscribers.set(summary.subscribers));
  }
}
```

Trasferisci il risultato al client con lo state transfer di Angular, così il
valore sopravvive all'hydration senza una seconda richiesta.

<Callout type="warn">
Il Pattern 2 compila comunque i riferimenti a `TrattoService` nel bundle del
browser — solo la *chiave* resta lato server. Preferisci il Pattern 1 ogni volta
che il dato non deve stare nell'HTML iniziale.
</Callout>

## Tipizzare i dati nel browser

Non esiste un pacchetto di tipi separato, e non serve. `@tratto/email` esporta
tutti i tipi di richiesta e risposta, e `import type` viene cancellato in fase di
compilazione: nel bundle non arriva nulla.

```ts
import type { EmailEvent } from '@tratto/email';

export interface DeliveryRow {
  event: EmailEvent;
}
```

Scrivi `import type`, non `import`. Con `verbatimModuleSyntax` TypeScript emette
l'import così com'è, trascinando l'intero SDK nel bundle browser. Attiva
`@typescript-eslint/consistent-type-imports` per farlo verificare dal linter.

È preferibile restituire dal server un oggetto ristretto e tipizzare quello: il
browser non ha motivo di ricevere un `EmailDetail` completo per mostrare una
stringa di stato.

## AnalogJS e Nitro

[AnalogJS](https://analogjs.org) è il meta-framework Angular costruito su Nitro.
Le sue route API server sono l'equivalente del Pattern 1:

```ts
// src/server/routes/api/contact.post.ts
import { defineEventHandler, readBody, createError } from 'h3';
import { Tratto } from '@tratto/email';

const tratto = new Tratto(process.env['TRATTO_API_KEY']!);

export default defineEventHandler(async (event) => {
  const body = await readBody(event);

  if (typeof body?.email !== 'string') {
    throw createError({ statusCode: 400, statusMessage: 'Invalid payload' });
  }

  const result = await tratto.emails.send({
    from: 'Acme <hello@mail.acme.com>',
    to: 'support@acme.com',
    replyTo: body.email,
    subject: 'Nuovo messaggio dal form di contatto',
    text: String(body.message ?? ''),
  });

  return { id: result.id };
});
```

I file sotto `src/server/` vengono impacchettati da Nitro nell'output server e
non raggiungono mai il browser.

## Fornire la chiave

Leggi la chiave dall'ambiente. Non committarla mai e non metterla in
`environment.ts`: i file environment di Angular fanno parte del bundle browser.

```bash
# .env — in gitignore
TRATTO_API_KEY=tratto_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

In sviluppo usa chiavi `tratto_test_...`, così un errore non può inviare email
reali.

## Gestione degli errori

I metodi dei servizi restituiscono `Observable` RxJS ed espongono i fallimenti
come `HttpErrorResponse` di Angular:

```ts
import { catchError, EMPTY } from 'rxjs';

emails
  .send({ from: '...', to: '...', subject: '...', html: '...' })
  .pipe(
    catchError((err) => {
      // Logga solo lato server — mai restituire l'errore grezzo al browser.
      console.error(err.status, err.error?.error?.code);
      return EMPTY;
    }),
  )
  .subscribe(({ id }) => console.log(id));
```

Al client restituisci un messaggio generico. I payload di errore di Tratto possono
contenere indirizzi dei destinatari e altri dettagli che non devono uscire dal tuo
server. Vedi [Codici di Errore](/it/docs/error-codes).

## Checklist

- [ ] `provideTratt` compare solo in `app.config.server.ts`, mai in `app.config.ts`
- [ ] La chiave arriva da `process.env`, non da `environment.ts`
- [ ] Nessun componente raggiungibile dal browser chiama Tratto senza guardia server
- [ ] I tuoi endpoint validano l'input prima di inoltrarlo a Tratto
- [ ] `from` è un indirizzo fisso e verificato, mai costruito da input utente
- [ ] Gli errori sono loggati sul server e restituiti al client in forma generica
- [ ] `grep -r "tratto_live" dist/browser` non trova nulla dopo una build di produzione

Quest'ultimo controllo è quello che conta davvero. Mettilo in CI.
