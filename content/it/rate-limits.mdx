# Rate Limit e Quote

## Rate Limit Globale

**500 richieste al minuto** per tenant. Il limite vale per tutti gli endpoint dell'API considerati insieme.

## Header di Rate Limit

Ogni risposta include le informazioni sul rate limit:

```http
X-RateLimit-Limit: 500
X-RateLimit-Remaining: 245
X-RateLimit-Reset: 1625084400
```

## Verificare lo Stato del Rate Limit

Prima di raggiungere il limite, controlla gli header:

```bash
curl -i https://api.tratto.email/v1/emails \
  -H "Authorization: Bearer tratto_live_..."
```

Restituisce gli header con le richieste rimanenti e l'orario di reset.

## Rate Limit Superato (429)

Quando superi il limite:

```json
{
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Too many requests. Try again after 60 seconds.",
    "retryAfter": 60
  }
}
```

## Strategia di Retry

Usa un **backoff esponenziale con jitter**:

```javascript
async function sendWithRetry(request, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await fetch(request);
    } catch (error) {
      if (error.status === 429) {
        const delay = Math.pow(2, attempt) * 1000 + Math.random() * 1000;
        await new Promise(r => setTimeout(r, delay));
      } else {
        throw error;
      }
    }
  }
}
```

## Quote di Volume Email

Limiti per piano (finestra mobile di 30 giorni):

| Piano | Email Mensili | Limite Giornaliero |
|------|---|---|
| Free | 1.000 | 33 |
| Starter | 10.000 | 333 |
| Growth | 100.000 | 3.333 |
| Pro | Illimitate | Illimitato |

Se superi la quota ottieni l'errore `PLAN_LIMIT_EXCEEDED`.

## Comportamento nei Picchi

I picchi brevi (nell'ordine dei secondi) possono superare `X-RateLimit-Remaining` a causa dell'elaborazione asincrona. Il limite di 500 req/min è un tetto rigido, ma i picchi brevi sono ammessi se la media resta sotto la soglia.
