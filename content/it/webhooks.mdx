# Webhook: Setup, Eventi e Verifica Firma

I **webhook** sono callback HTTP che notificano la tua app quando si verificano eventi (email consegnata, aperta, rimbalzata, ecc.). Invece di eseguire il polling dell'API, Tratto ti spinge gli eventi in tempo reale.

## Registra un Webhook

Crea un endpoint webhook.

**cURL**
```bash
curl -X POST https://api.tratto.email/v1/webhooks \
  -H "Authorization: Bearer tratto_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "url":"https://tuoapi.com/webhooks/tratto",
    "events":["sent","delivered","opened","clicked","bounced","complained","unsubscribed"]
  }'
```

**Risposta:**
```json
{
  "data": {
    "id": "wh_abc123",
    "url": "https://tuoapi.com/webhooks/tratto",
    "events": ["sent", "delivered", "opened", "clicked", "bounced", "complained", "unsubscribed"],
    "secret": "whsec_xyz789...",
    "createdAt": "2025-06-30T12:00:00Z"
  }
}
```

**Salva il `secret`** — lo userai per verificare le firme.

## Eventi Webhook

Tratto invia richieste `POST` al tuo URL quando si verificano questi eventi:

| Evento | Payload |
|--------|---------|
| `sent` | Email accettata dal server di posta |
| `delivered` | Server di posta ha confermato consegna |
| `opened` | Destinatario ha aperto l'email (pixel tracciato) |
| `clicked` | Destinatario ha cliccato un link |
| `bounced` | Server di posta ha rifiutato consegna |
| `complained` | Destinatario ha segnalato come spam |
| `unsubscribed` | Destinatario ha cliccato annulla iscrizione |

## Payload Webhook

**Esempio:**
```json
{
  "id": "evt_abc123",
  "type": "delivered",
  "emailId": "email_xyz789",
  "recipient": "user@example.com",
  "occurredAt": "2025-06-30T12:00:10Z",
  "data": {}
}
```

## Verifica Firma Webhook

Ogni consegna porta un header `X-Tratto-Signature`. **Non** è un hash nudo:
contiene un timestamp e la firma.

```http
X-Tratto-Signature: t=1784977714054,v1=0b37dd97144dcdf176572a1b...
```

La stringa firmata è il timestamp e il corpo grezzo uniti da un punto:

```
{timestamp}.{rawBody}
```

La verifica ha quindi quattro passi: estrarre `t` e `v1`, rifiutare i timestamp
fuori dalla finestra di tolleranza, ricalcolare l'HMAC su `{t}.{rawBody}` e
confrontare con `v1` a tempo costante.

**[Verifica della Firma dei Webhook](/it/docs/webhook-verification)** contiene le
implementazioni funzionanti per Node, runtime edge, Python e PHP, oltre al
comportamento di consegna e retry da tenere presente.

<Callout type="warn">
Firmare il solo corpo, o confrontare direttamente l'header con un digest, non
corrisponderà mai. Sono i due errori che vediamo più spesso.
</Callout>

## Prevenire i Replay Attack

Usa il campo `t` dell'header della firma, non `occurredAt` del payload. `t` è
coperto dalla firma e registra quando la consegna è stata firmata; `occurredAt`
registra quando è avvenuto l'evento, e i due valori divergono nei retry.

Il controllo di tolleranza è già incluso nelle implementazioni in
[Verifica della Firma dei Webhook](/it/docs/webhook-verification).

## Ruota il Segreto Webhook

Genera un nuovo segreto di firma.

**cURL**
```bash
curl -X POST https://api.tratto.email/v1/webhooks/wh_abc123/rotate-secret \
  -H "Authorization: Bearer tratto_live_..."
```

**Risposta:**
```json
{
  "data": {
    "secret": "whsec_new..."
  }
}
```

<Callout type="warn">
La rotazione ha effetto **immediato**: non esiste una finestra di sovrapposizione
e il secret precedente smette di funzionare appena viene emesso quello nuovo. Per
ruotare senza perdere consegne, pubblica prima un endpoint che accetti entrambi i
secret, poi ruota, poi rimuovi il vecchio. Vedi
[Rotazione del secret](/it/docs/webhook-verification).
</Callout>

La rotazione azzera anche il contatore dei fallimenti e riabilita un webhook che
era stato disattivato dopo ripetuti errori.

## Evento di Test

Invia un evento webhook di test per verificare la configurazione.

**cURL**
```bash
curl -X POST https://api.tratto.email/v1/webhooks/wh_abc123/test \
  -H "Authorization: Bearer tratto_live_..."
```

Un evento `sent` di test viene postato al tuo URL immediatamente.

## Elenca i Webhook

Ottieni tutti i webhook registrati.

**cURL**
```bash
curl https://api.tratto.email/v1/webhooks \
  -H "Authorization: Bearer tratto_live_..."
```

## Consegne Webhook

Visualizza la cronologia delle consegne per un webhook.

**cURL**
```bash
curl https://api.tratto.email/v1/webhooks/wh_abc123/deliveries \
  -H "Authorization: Bearer tratto_live_..."
```

**Risposta:**
```json
{
  "data": [
    {
      "id": "del_001",
      "webhookId": "wh_abc123",
      "eventId": "evt_abc123",
      "status": "success",
      "statusCode": 200,
      "deliveredAt": "2025-06-30T12:00:10Z"
    },
    {
      "id": "del_002",
      "webhookId": "wh_abc123",
      "eventId": "evt_def456",
      "status": "failed",
      "statusCode": 500,
      "retries": 3,
      "nextRetryAt": "2025-06-30T12:10:00Z"
    }
  ]
}
```

Tratto riprova le consegne fallite fino a 3 volte.

## Elimina un Webhook

Annulla la registrazione di un webhook.

**cURL**
```bash
curl -X DELETE https://api.tratto.email/v1/webhooks/wh_abc123 \
  -H "Authorization: Bearer tratto_live_..."
```
