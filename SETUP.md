# Tratto Docs — architecture and deployment

## Stack

| Layer | Choice |
|---|---|
| Framework | Next.js 15.5 (App Router) + React 19 |
| Docs engine | Fumadocs (`fumadocs-core` / `fumadocs-ui` 15.8, `fumadocs-mdx` 11) |
| Styling | Tailwind v4 (CSS-first `@theme`) + Tratto design tokens |
| i18n | `next-intl` 4.13, always-explicit locale prefix |
| Search | Orama, self-hosted — no third-party search account |
| Hosting | Firebase App Hosting |

Node 22 is required (`.nvmrc`, `engines`).

## Prerequisites

- Node.js 22+
- pnpm 10+

## Installation

```bash
pnpm install          # `postinstall` runs `fumadocs-mdx` to generate `.source/`
pnpm dev
```

## Project structure

Only the paths the rules refer to (`git ls-files` for the full list):

```
app/[locale]/docs/[[...slug]]/page.tsx   # MDX pages
app/[locale]/docs/api-reference/         # endpoint list from public/openapi.json
app/api/{search,og}/                     # Orama search, 1200×630 OG images
app/{sitemap,robots}.ts                  # both locales, hreflang; noindex on staging
app/globals.css                          # Tailwind v4 + the three token bridges (below)
app/design-tokens.css                    # verbatim copy of tratto/packages/design-tokens/tokens.css
content/{en,it}/*.mdx                    # the documentation
lib/{i18n,site,source}.ts                # toLocale · docsPath/absoluteUrl · loader + hasTranslation
i18n/{routing,request}.ts, middleware.ts # next-intl, locale redirect
source.config.ts                         # frontmatter schema (draft, updatedAt)
scripts/sync-openapi.js                  # runs before every build
apphosting.yaml, apphosting.staging.yaml # App Hosting prod / staging overlay
lighthouserc.json, .github/workflows/ci.yml
```

`.source/` is generated by `fumadocs-mdx` and is not committed.

## Design tokens

`app/design-tokens.css` is the shared Tratto token file, copied verbatim from
`tratto-email/tratto` so both frontends stay in sync. Treat it as read-only,
and verify the copy is still byte-identical before touching anything near it:

```bash
cmp app/design-tokens.css <(git -C ../tratto show origin/develop:packages/design-tokens/tokens.css)
```

`globals.css` layers three docs-specific concerns on top:

1. **Theme toggle bridge.** The shared file switches on `prefers-color-scheme`;
   the docs also ship a manual theme switcher. Without the `.light` / `.dark`
   class overrides, an explicit choice loses to the OS setting.
2. **Fumadocs mapping.** `--color-fd-*` is mapped onto token *names*, so the
   dark palette flows through with a single mapping block.
3. **Font wiring.** The shared file names families literally (`'Inter'`), which
   assumes a global stylesheet. Next self-hosts them via `next/font` under
   hashed names, so the three font tokens are repointed at those variables.

The values that are easy to get wrong (14px base, `--color-paper` vs
`--color-white`, radius, shadows) are listed in `CLAUDE.md`, rule 5.

## Routing

URLs always carry the locale: `/en/docs/quickstart`, `/it/docs/quickstart`.
Requests to `/` are redirected to `/en` by `middleware.ts`.

Content is resolved with Fumadocs' `dir` parser, so `content/it/x.mdx` serves
`/it/docs/x`. When a page has no translation for a locale, Fumadocs falls back
to English. `lib/source.ts` exposes `hasTranslation()` so the sitemap and the
hreflang tags can tell a real translation from a fallback.

### A known version quirk

`fumadocs-mdx@11` returns `source.files` as a lazy factory while
`fumadocs-core@15` still expects a plain array. `lib/source.ts` normalises this
in one place. If Fumadocs is upgraded to 16 (which also requires Next 16), that
shim can be deleted.

## OpenAPI spec sync

`scripts/sync-openapi.js` runs before every build and tries, in order:

1. `$TRATTO_OPENAPI_URL` (set per environment in `apphosting*.yaml`)
2. `https://api-staging.tratto.email/docs/json`
3. `https://api.tratto.email/docs/json`
4. the existing `public/openapi.json`
5. `public/openapi-template.json`

`public/openapi.json` is gitignored — it is a build artefact. The build never
fails because the API is unreachable; it falls back to the committed template.

Production answers **404** on `/docs/json` (`API_DOCS_ENABLED=false` in
`tratto-api`'s production deploy; tratto-api#439), so today the reference is
built from the staging spec. `CLAUDE.md` § "The API contract" has the details
and the pre-rollout check.

## Analytics and consent

GTM/GA4 is consent-gated at the container level, not just the tag level: the
GTM container script (`components/google-tag-manager.tsx`) is only injected
into the page once the visitor has actually granted analytics consent —
before that, Google Consent Mode defaults are set (`analytics_storage: denied`,
etc.) via a tiny inline script, but GTM itself never loads. This is stricter
than relying on Consent Mode alone to suppress tags, since no third-party
script runs at all pre-consent.

- `lib/cookie-prefs.ts` stores the decision (`localStorage`) and broadcasts
  it via the `tratto:consent-updated` event whenever it changes (banner
  accept/decline, or the preferences modal).
- `components/google-tag-manager.tsx` listens for that event (and checks
  stored prefs on mount, for returning visitors) before rendering the GTM
  `<Script>` tag.
- `components/cookie-consent.tsx` / `cookie-preferences-modal.tsx` are the
  only things that call `pushConsentUpdate()` — that's what fires the event.

This exact pattern (same file names, same event name) is intentionally
duplicated in the `tratto` marketing site's `src/lib/cookie-prefs.ts` /
`src/components/ui/GoogleTagManager.tsx` — not shared as a package, since the
two Next.js apps are separate deploys. If you change the consent-gating logic
here, check whether the same fix applies there too, and vice versa.

## SEO

- `generateMetadata()` on every page: title (`{Page} — Tratto Docs`),
  description from frontmatter, canonical, OpenGraph, and a dynamic OG image.
- `hreflang` for `en`, `it` and `x-default`, emitted only for locales that have
  a real translation.
- Untranslated pages set their canonical to the English URL, so the fallback
  never registers as duplicate content.
- `draft: true` pages are `noindex` and excluded from the sitemap.
- Security headers (CSP, HSTS, X-Frame-Options, X-Content-Type-Options,
  Referrer-Policy, Permissions-Policy) are set in `next.config.ts`.
- Staging serves `Disallow: /` plus `X-Robots-Tag: noindex`, keyed off
  `NEXT_PUBLIC_SITE_URL`.

After the first production deploy, submit
`https://docs.tratto.email/sitemap.xml` to Google Search Console.

## Branching and deployment

There is no `develop` branch.

```
<type>/<slug>  →  PR → main  →  merge  →  production + staging deploy (both from main)
```

Firebase App Hosting deploys automatically on push to `main`. Both backends
track `main` and roll out the same commit in parallel, so staging is not a gate
before production:

| Branch | Backend | Config actually applied | Domain |
|---|---|---|---|
| `main` | prod (GCP `trattoemail`) | `apphosting.yaml` | docs.tratto.email |
| `main` | staging (GCP `tratto-staging`) | `apphosting.yaml` + `apphosting.staging.yaml` (see below) | tratto-docs--tratto-staging.europe-west4.hosted.app |

The `tratto-staging` backend has environment name `staging` (checked
2026-09-14), so App Hosting merges `apphosting.staging.yaml` over
`apphosting.yaml`. Variables the staging file does not repeat keep their
production value. It overrides all three today: `NEXT_PUBLIC_SITE_URL`
(noindex), `TRATTO_OPENAPI_URL` (staging spec) and `NEXT_PUBLIC_GTM_ID`
(`none`: no GTM, since App Hosting treats empty strings as reserved and the
layout loads GTM only for IDs starting with `GTM-`).

### Rollout check runs

Only the merge commit on `main` carries the two
`App Hosting - Rollout (…/tratto-docs)` check runs (branch commits have none,
which is normal). They complete roughly four minutes after the merge, and on
some merge commits one backend's check run never shows up: 23e0ed1
(2026-09-14) reports only `trattoemail`, 9f49fb2 only `tratto-staging`. It is
not specific to one backend, and it is unresolved whether the rollout failed
to start or only failed to publish its check — the installed `gcloud` has no
App Hosting surface to settle it. When one is missing, confirm against the
served site (`curl` + `grep` on docs.tratto.email and the staging host)
instead of assuming either outcome.

`.github/workflows/ci.yml` runs lint, typecheck and build on every PR to and
push on `main`. There is no `paths` filter, so every PR costs one run (about
one minute) and every merge a second one.

### Releases

Releases share one version with `tratto-api`, `tratto-app` and `tratto` (the
SDKs are versioned separately). Bump `package.json` in the PR that accompanies
the release (there is no `develop` to put it on), then tag the `main` commit
that published it:

```bash
gh release create vX.Y.Z --target "$(git rev-parse origin/main)" --title vX.Y.Z --generate-notes
```

`--target` needs the **full 40-character sha** — a short sha is rejected with
`HTTP 422 … Release.target_commitish is invalid` (`../CLAUDE.md`, lesson 10).

### One-time setup still required in the consoles

These cannot be done from the repository:

- Map the custom domain `docs.staging.tratto.email` (no DNS record yet).
- Enable branch protection on `main` (require PR + passing CI).
- Submit the sitemap to Google Search Console.
