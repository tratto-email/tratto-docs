# Tratto Docs — architecture and deployment

## Stack

| Layer | Choice |
|---|---|
| Framework | Next.js 15.5 (App Router) + React 19 |
| Docs engine | Fumadocs (`fumadocs-core` / `fumadocs-ui` 15.8, `fumadocs-mdx` 11) |
| Styling | Tailwind v4 (CSS-first `@theme`) + Tratto design tokens |
| i18n | `next-intl` 4.13, always-explicit locale prefix |
| Search | Orama, self-hosted — no third-party search account |
| Hosting | Firebase App Hosting |

Node 22 is required (`.nvmrc`, `engines`).

## Prerequisites

- Node.js 22+
- pnpm 10+

## Installation

```bash
pnpm install          # `postinstall` runs `fumadocs-mdx` to generate `.source/`
pnpm dev
```

`.source/` is generated by `fumadocs-mdx` and is not committed.

## Routing

URLs always carry the locale: `/en/docs/quickstart`, `/it/docs/quickstart`.
Requests to `/` are redirected to `/en` by `middleware.ts`.

Content is resolved with Fumadocs' `dir` parser, so `content/it/x.mdx` serves
`/it/docs/x`. When a page has no translation for a locale, Fumadocs falls back
to English. `lib/source.ts` exposes `hasTranslation()` so the sitemap and the
hreflang tags can tell a real translation from a fallback.

### A known version quirk

`fumadocs-mdx@11` returns `source.files` as a lazy factory while
`fumadocs-core@15` still expects a plain array. `lib/source.ts` normalises this
in one place. If Fumadocs is upgraded to 16 (which also requires Next 16), that
shim can be deleted.

## OpenAPI spec sync

`scripts/sync-openapi.js` runs before every build and tries, in order:

1. `$TRATTO_OPENAPI_URL` (set per environment in `apphosting*.yaml`)
2. `https://api-staging.tratto.email/docs/json`
3. `https://api.tratto.email/docs/json`
4. the existing `public/openapi.json`
5. `public/openapi-template.json`

`public/openapi.json` is gitignored — it is a build artefact. The build never
fails because the API is unreachable; it falls back to the committed template.

## SEO

- `generateMetadata()` on every page: title (`{Page} — Tratto Docs`),
  description from frontmatter, canonical, OpenGraph, and a dynamic OG image.
- `hreflang` for `en`, `it` and `x-default`, emitted only for locales that have
  a real translation.
- Untranslated pages set their canonical to the English URL, so the fallback
  never registers as duplicate content.
- `draft: true` pages are `noindex` and excluded from the sitemap.
- Security headers (CSP, HSTS, X-Frame-Options, X-Content-Type-Options,
  Referrer-Policy, Permissions-Policy) are set in `next.config.ts`.
- Staging serves `Disallow: /` plus `X-Robots-Tag: noindex`, keyed off
  `NEXT_PUBLIC_SITE_URL`.

After the first production deploy, submit
`https://docs.tratto.email/sitemap.xml` to Google Search Console.

## Branching and deployment

```
feat/<slug>  →  PR → develop  →  docs.staging.tratto.email
                                     ↓ (release PR)
                                   main  →  docs.tratto.email
```

Firebase App Hosting deploys automatically on push:

| Branch | Backend | Config | Domain |
|---|---|---|---|
| `main` | prod (GCP `trattoemail`) | `apphosting.yaml` | docs.tratto.email |
| `develop` | staging (GCP `tratto-staging`) | `apphosting.staging.yaml` | docs.staging.tratto.email |

`.github/workflows/ci.yml` runs lint, typecheck and build on every PR to `main`
or `develop`.

### One-time setup still required in the consoles

These cannot be done from the repository:

- Create the two App Hosting backends and point them at this repo/branches.
- Map the custom domains `docs.tratto.email` and `docs.staging.tratto.email`.
- Enable branch protection on `main` and `develop` (require PR + passing CI).
- Submit the sitemap to Google Search Console.
